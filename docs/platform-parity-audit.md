## Initial gaps found independently in Sprout (before implementation)

- There is no verified first-party fundamentals feed for market capitalization, volume, financial statements, ratios or company events. Removed visible undated sample metrics rather than presenting them as current.
- No dedicated news feed, economic/earnings calendar or fundamental screener page was found in the route/component inventory. Whether any is in scope depends on verifying the reference.
- Exchange data for virtual fills is not connected. Switching saved portfolios to a new valuation feed would require an explicit compatibility/migration plan; do not silently reprice historical fills or balances.
- Data-provider credentials, subscriptions, exchange entitlements, redistribution/display rights and timestamp/delay requirements must be identified per verified integration. The existing embedded quote widget is distinct from an API license for simulator execution or fundamentals.
- Asset catalog provenance, listing refresh process, corporate-action handling and vendor licensing need verification before production claims of full current market coverage.

## Data, licensing and preservation

- **SEC EDGAR:** public submissions/company-ticker/company-facts endpoints, fixed server hosts, validated ticker/filing paths, declared User-Agent, conservative per-instance request queue, one-hour response caching. Full facts are not placed in Next’s size-limited fetch cache. No API key is required. Fact coverage is explicitly US-GAAP/USD; absent values are not zero. Follow [SEC fair access](https://www.sec.gov/about/developer-resources). Multi-instance production traffic may require a shared cache/rate limiter.
- **TradingView widgets:** official external widgets with visible attribution/source links; no underlying vendor feed scraping, redistribution or use in simulator fills. Widget/provider/exchange availability and delay indicators apply. Users may need to open provider links if third-party content is blocked.
- **No real execution-feed change:** existing deterministic paper fills, balances, trade records, portfolio snapshots and generated ticker remain unchanged and labeled. SEC/TradingView data never silently reprice saved accounts.
- **Budget saves:** optional `budgetGame` field in the existing account JSON stores assumptions and decisions. Balances are deterministically reconstructed and validated. Old accounts still validate; no database migration, auth/RLS changes or trading/XP writes are required. New conditional orders use optional kind/anchor/distance/expiry fields; old limit orders keep their existing trigger logic.
- **Curriculum:** added IDs 200–227, levels 46–52; no old IDs, archived progress or account values are repurposed. The original core-completion badge remains earned for existing completers; a separate expanded-curriculum badge tracks the new library. Existing Starter/Pro gating applies. The new topics flow through the existing modules, quizzes, classroom assignment picker and live-game catalog. The existing database limit of 159 selected lessons per classroom assignment is retained (the UI assigns a module at a time); this is independent of the live-game question count.
- **Original explanations:** education sources for factual review include [CFPB](https://www.consumerfinance.gov/consumer-tools/), [FDIC](https://www.fdic.gov/resources/deposit-insurance/), [IRS](https://www.irs.gov/individuals), [Investor.gov](https://www.investor.gov/), [Federal Reserve](https://www.federalreserve.gov/) and original SEC filings. These links are references, not claims of endorsement or a copied curriculum.
